# /bid-run — 採購案件流程驅動

參數：`$ARGUMENTS`（第一個字是案號；其後是動作，沒有動作就表示「從目前進度繼續」）。
所有狀態由 `python3 採購流程/procure.py` 管理；你只負責讀檔、擬稿、核對。鐵則見根目錄 CLAUDE.md，違反鐵則比做不完更糟。

## 0. 定位

```bash
python3 採購流程/procure.py use <案號>        # 案號存在就切換；不存在就看下一條
python3 採購流程/procure.py status --json      # 讀 current / current_dir / current_step_file / config
```

- 案號不存在：`procure.py new <案號> --title "<案名>" [--budget N --unit …]`（流程預設「待判斷」，判斷步驟確認後才 replan）。案名不知道就先不填，收件後用 `set` 補。接著提醒承辦人把業務單位的簽與招標文件放進 `cases/<案號>/00-input/`；資料夾是空的就停下來等，不要憑空做。
- 回傳的 JSON 裡 `current` 為 null 表示全案完成，只回報狀態。

## 1. 依動作分流

| 動作 | 做法 |
|---|---|
| （無）／繼續 | 看 `current.status`：`pending` → 執行第 2 節；`in_progress` → 接續第 2 節（讀已有的工作稿，不要重來）；`awaiting_confirm` → **不做新東西**，把待確認事項再列一次，結束回合。 |
| 確認 | `procure.py confirm --note "<承辦人這次確認的重點>"`。若剛確認的是「判斷」階段：先 `procure.py replan <流程範本>` 與 `set 招標方式/決標方式`，再 confirm。然後**立即**執行下一階段的第 2 節（這就是「確認後自動進下一步」）。 |
| 修改 <意見> | `procure.py revise "<意見>"`，只改被指出的部分，重產 docx，再 `submit`，結束回合請再次確認。 |
| 跳過 | `procure.py skip --reason "<理由>"`，接著執行下一階段的第 2 節。 |
| 契變／後續擴充／分期驗收 | `procure.py add <種類>`（履約中要立即處理加 `--now`）；若目前階段正待確認就先提醒承辦人確認。接著依狀態繼續。 |
| 暫停 | 什麼都不改，回報狀態與下一步，結束回合。 |
| 狀態 | `procure.py status`，回報，結束。 |
| 匯出 | `procure.py export [--stage …]`，回報檔案位置。 |
| 新案 … | 同第 0 節建案；後面的文字當作案名。 |

承辦人在聊天中直接回「確認」「OK」「修改：…」「跳過」「契變」等，也視為對目前案件的這些動作（CLAUDE.md 有同樣規則）。

## 2. 執行目前階段（每個階段都一樣的骨架）

1. `python3 採購流程/procure.py start`（複製範本到階段資料夾；已有的檔不覆蓋）。
2. 讀 `current_step_file`（`採購流程/steps/…`）並**完全照做**；步驟 7 以後先讀 `steps/_common-memo.md`。
3. 先讀再寫：`cases/<案號>/STATE.md`（已確認事項與承辦人決定）、前面階段的工作稿、`reference/舊檔/`、`00-input/`。舊檔只借格式與用語，數值一律不得帶入。
4. 產出寫進 `current_dir`。事實性資料（家數、報價、評分、日期、文號）沒有來源就寫 `【待補：…】`，並在結尾列出需要承辦人提供的資料。
5. 承辦人在對話中做的決定用 `procure.py decide "…"` 記下；要承辦人自己做的事用 `procure.py todo "…"`。
6. `python3 採購流程/procure.py submit`。
7. **結束回合**，用下面格式回報；不得自動進入下一階段，不得連做兩步。

```
【<案號> 第 N 步 <階段名>】已完成，待您確認
成果：
- <檔案路徑>：一句話說明
待您確認：
- <這一步的 confirm 事項，逐條>
需要您補的資料／自行處理：
- …
回覆「確認」進下一步（<下一階段名>）、「修改：…」退回修改、「跳過」略過本步。
```

可用 AskUserQuestion 的環境，用它給「確認 / 修改 / 跳過」三個選項；不可用就以上面文字結束回合。

## 3. 特殊情況

- **流標要第二次招標**：不要新建案號。`procure.py revise` 把「開標」退回，承辦人決定後用 `procure.py confirm --force` 跳過已做的階段再回到「公告與等標期」；或建議承辦人以「案號-2」另建案，由承辦人決定。
- **履約管理階段**可停留很久：每次進來只更新紀錄並詢問是否插入臨時階段；承辦人回「暫停」就維持。
- **轉檔工具缺少**（pdftotext、soffice、python-docx）：說明缺什麼並改用能用的方式（直接讀 PDF、只出 Markdown），不要假裝做完。
- **找不到 reference/舊檔/**：照 templates 做，並提醒承辦人補舊檔以提高用語一致性。
